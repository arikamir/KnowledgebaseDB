# Data Model: Argo CD GitOps Application Delivery

The delivery model is intentionally declarative. Git stores release intent and
immutable references; Argo CD and CI produce observed records outside the
desired-state files.

## Release Bundle

CI-produced evidence for one build and publication attempt.

| Field | Type | Required | Validation / meaning |
| --- | --- | --- | --- |
| `environment` | enum | yes | Explicit target; initially `nonprod`. |
| `releaseVersion` | SemVer 2.0.0 string | yes | One unique release identity; prerelease/build metadata allowed. |
| `sourceRevision` | lowercase SHA-1 string | yes | Exactly 40 hexadecimal characters for the reviewed source revision. |
| `services.ui.image` | OCI reference | yes | ACR repository plus immutable `@sha256` digest. |
| `services.bff.image` | OCI reference | yes | ACR repository plus immutable `@sha256` digest. |
| `services.core.image` | OCI reference | yes | ACR repository plus immutable `@sha256` digest. |
| `validationEvidence` | artifact links/records | yes | CI scan, contract, and compatibility evidence; never credential material. |
| `ciRun` | provider run identifier | yes | Links the bundle to the originating GitHub Actions run. |
| `sourceTag` | protected Git tag | yes | Normalized SemVer tag that points to `sourceRevision`. |

Relationship: exactly one Release Bundle produces one Release Declaration. All
three service image digests are validated as one unit.

## Release Declaration

The reviewed Git file consumed by the ApplicationSet at
`deploy/argocd/environments/<environment>/release.json`.

| Field | Type | Required | Validation / meaning |
| --- | --- | --- | --- |
| `schemaVersion` | integer | yes | `1` for this contract. |
| `environment` | enum | yes | Initially `nonprod`; must equal the containing directory. |
| `releaseVersion` | SemVer 2.0.0 string | yes | Must be unique across declarations and match the bundle. |
| `sourceRevision` | lowercase SHA-1 string | yes | Must identify the reviewed source revision. |
| `services` | object | yes | Exact keys: `ui`, `bff`, `core`. |
| `services.<name>.image` | OCI reference | yes | Exact ACR digest reference, no mutable tag. |

The declaration is generated only for a protected tag and is merged through the
approved-automated-review bot-branch pull request. The namespace-scoped
`career-agent-acr-pull` Secret is deliberately not part of this entity.

State transition: `candidate` (generated by CI) -> `reviewed` (merged to
protected `main`) -> `reconciled` or `failed` (observed by Argo CD). A failed
declaration is not edited in place to hide history; rollback is a reviewed Git
reversion to a previously healthy declaration.

## Generated Application

The ApplicationSet renders one Argo CD `Application` named
`career-agent-<environment>`.

| Field | Type | Meaning |
| --- | --- | --- |
| `metadata.labels` | map | Environment and SemVer identity for search/audit. |
| `metadata.annotations` | map | Source revision and declaration path. |
| `spec.project` | string | Restricted `career-agent` AppProject. |
| `spec.source` | repo/path/kustomize | Protected `main` plus the app-only overlay; three image substitutions come from the declaration. |
| `spec.destination` | server/namespace | Existing cluster and `career-agent` namespace only. |
| `spec.syncPolicy` | automated/retry/options | Self-heal, prune, bounded retry, and no namespace creation. |

Managed resources are UI, BFF, and Core namespace-scoped workload resources
allowed by the AppProject. Namespace, Gateway/API routing, private load balancer,
platform controllers, Azure resources, and Terraform state are not related to
this entity and must remain infrastructure-owned.

## Sync Record

An observed Argo CD/application evidence record, retained by the operations
system or exported audit store.

| Field | Type | Required | Meaning |
| --- | --- | --- | --- |
| `schemaVersion` | integer | yes | `2`; this version uses the vendor-neutral `automatedReview` result. |
| `repository` | string | yes | GitHub repository associated with the evidence. |
| `branch` | string | yes | Desired-state branch associated with the evidence. |
| `eventType` | enum | yes | `release`, `sync`, or `rollback`. |
| `actorType` | enum | yes | `automation` or `human`; selects the required actor record. |
| `desiredStateRevision` | Git SHA | yes | `main` revision that generated the Application. |
| `releaseVersion` | SemVer | yes | Version from the declaration. |
| `imageDigests` | map of three strings | yes | Exact digests applied to UI/BFF/Core. |
| `syncStatus` | enum | yes | `Synced`, `OutOfSync`, `Unknown`, or `Failed`. |
| `healthStatus` | enum | yes | Argo health result and reason. |
| `affectedService` | service name | conditional | UI, BFF, or Core service affected by a failed rollout. |
| `nextAction` | string | conditional | Operator-safe remediation step for a failed or blocked release. |
| `observedAt` | timestamp | yes | UTC observation time. |
| `diagnosedAt` | timestamp | conditional | Time the failure was diagnosed for SC-005 measurement. |
| `nextActionVisibleAt` | timestamp | conditional | Time the recommended next action became visible to the operator. |
| `failureReason` | string | conditional | Actionable error when sync/health is not successful. |
| `automationIdentity` | principal reference | conditional | Argo/controller or CI identity when automation performed the action. |
| `humanAction` | tenant/subject/role record | conditional | Required when a human approved, synchronized, or rolled back the release; contains no credential material. |
| `validationEvidence` | artifact links | yes | Contract, scan, and compatibility evidence. |
| `readiness` | readiness record | yes | Platform readiness status and observation time. |
| `rollback` | rollback record | conditional | Required for rollback events. |

Timing evidence additionally records `mergedAt`, `syncStartedAt`,
`healthyAt`/`failedAt`, and `driftDetectedAt` so the 10-minute merge-to-sync,
two-minute diagnosis, and five-minute drift criteria can be calculated.

## Platform Readiness Record

Identityless or least-privilege readiness result consumed before application
release hand-off.

| Field | Type | Required | Meaning |
| --- | --- | --- | --- |
| `schemaVersion` | integer | yes | Versioned readiness contract. |
| `status` | enum | yes | `ready` or `blocked`. |
| `environment` | enum | yes | Explicit target, initially `nonprod`. |
| `checks` | map | yes | Named results for namespace, AppProject, pull secret, registry, and workload prerequisites. |
| `observedAt` | timestamp | yes | UTC observation time. |
| `failureReason` | string | conditional | Actionable reason when `status` is `blocked`. |

The readiness command may inspect prerequisites but must not create or mutate
Azure, namespaces, Secrets, or workloads.

## Rollback Record

An auditable Git reversion and resulting reconciliation.

| Field | Type | Required | Meaning |
| --- | --- | --- | --- |
| `actor` | Entra subject | yes | Human approver or approved automation identity. |
| `actorRole` | enum | yes | Application-release or approved recovery role. |
| `environment` | enum | yes | Explicit target environment. |
| `fromRevision` | Git SHA | yes | Failed/undesired desired-state revision. |
| `toRevision` | Git SHA | yes | Previously approved healthy revision. |
| `reason` | string | yes | Operator-supplied audited reason. |
| `result` | enum | yes | Approved, rejected, or reconciled. |
| `recordedAt` | timestamp | yes | UTC event time. |

Rollback changes only the Release Declaration on GitHub `main`; no Terraform
plan, cloud-resource mutation, or platform repair is part of the transition.

## Delivery Identity

| Identity | Scope | Must not have |
| --- | --- | --- |
| GitHub publisher workload identity | Push to ACR and write release evidence/PR | AKS write, Terraform state, Key Vault secret values |
| Platform bootstrap identity | Provision/rotate `career-agent-acr-pull` and other prerequisites | Routine application release mutation |
| Argo CD repository/controller identity | Read protected Git and reconcile the AppProject destination | Cluster-wide resources, Terraform, human impersonation |
| Application-release Entra role | Review/merge release declaration and request sync/rollback | Infrastructure administration |
| Infrastructure-admin Entra role | Terraform/platform bootstrap | Routine application release mutation |
| Read-only Entra role | View Applications, health, and evidence | Sync, rollback, Git write, or infrastructure changes |
